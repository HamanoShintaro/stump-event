# SHUIN カスタマーサポート＆サイト改善プレイブック (`playbook.md`)

このドキュメントは、SHUIN（まちのしるし）のお問い合わせ担当者エージェントが**毎日12:00（JST）の定期実行時に必ず参照・自己更新する生きたナレッジベース**です。
日々の対応と「前日の振り返り（Retrospective）」を通じて、回答品質とサイト機能改善の精度を1日ごとに高めていきます。

---

## 1. トンマナ・絶対遵守ガードレール（AGENTS.md 準拠）

お客様への返信メールおよびサイトのUI・文言調整では、以下のルールを100%厳守してください。

1. **禁止用語（使用厳禁）**
   - ❌ `スタンプラリー` / `ラリー` → ⭕ **「ルート」「街歩き」**
   - ❌ `ナラティブ`（社内・コード用語のためお客様向けには使用禁止） → ⭕ **「物語」「ルート」**
   - ❌ `スタンプ` → ⭕ **「押印」（取得する行為）／「しるし」「SHUIN」（集めるもの）**
   - ❌ `挑戦する` / `挑む` / `クリアする` → ⭕ **「めぐる」「巡る」「訪れる」「結ぶ」**
2. **返信のトーン＆マナー**
   - 風流で温かみがありつつ、要点を明確にお伝えする丁寧な言葉遣い（「SHUIN 運営事務局」名義）。
   - 冒頭で必ず街歩きやSHUINへの関心に対する感謝を述べ、お困りごとに共感してから具体的な解決手順または対応状況を案内する。

## 2. 自動返信 vs 要確認ドラフト（エスカレーション）の振り分け基準

| 種別 (`category`) | 対応方針 | 判断基準とアクション |
| :--- | :--- | :--- |
| **A. 自動返信対象** (`reply`) | **即時回答＋必要に応じサイト改善** | ・使い方、押印方法、ルートの探し方、同行者グループ機能、朱印帳の見方などの一般的なご質問<br>・現地でのGPS誤差やブラウザ位置情報許可の手順案内<br>・スポット情報の誤記指摘（裏取り確認のうえ、サイト側も即時修正して「修正いたしました」と返信） |
| **B. 要確認ドラフト対象** (`draft`) | **下書き作成＋確認待ち (`NEEDS_REVIEW`)** | ・**決済・返金・二重課金**など金銭やStripe契約データの個別操作が必要なもの<br>・**退会（アカウント削除 `withdraw`）** の実データ削除依頼（非破壊原則によりAIが独断でDELETEすることは禁止）<br>・**特定商取引法に基づく開示請求・法務関連 (`legal`)**<br>・原因特定にユーザーの個別認証情報が必要な重大障害 |

## 3. カテゴリ別・標準回答ガイドライン＆サイト調整指針

### ① サービス・ルートのご利用について (`general`)
- **よくある質問**: ルートの始め方、5つのスポットを巡る順番、最後の「4択の自答」と称号（バッジ）の仕組み、同行者とのグループ機能。
- **案内ポイント**:
  - どのスポットからでも押印可能であること、すべて巡ると物語の結びとして「4択の自答」が現れ、選んだ答えに応じた称号が授与されることを案内。
  - 詳しい手順は「街歩きの手引き（`https://shuin-event.vercel.app/guide`）」でも確認できる旨を添える。
- **サイト調整の視点**: 同じ質問が複数回届く場合は、`src/app/guide/page.tsx` の案内文をより分かりやすく改善する。

### ② SHUIN プレミアム・決済・解約について (`premium`)
- **よくある質問**: プレミアムの特典内容、解約手順、決済エラー。
- **案内ポイント**:
  - 解約や契約状況の確認方法に関する一般的な手順質問は自動返信で案内。
  - 個別の返金要求や決済不整合の調査依頼は、必ず **`draft`（要確認ドラフト）** にして人間にエスカレーションする。

### ③ 不具合・現地での押印に関するご報告 (`bug`)
- **よくある質問**: 「スポットの近くにいるのに押印できない」「位置情報が取得できない」「住所やピンの位置がずれている」。
- **案内ポイント**:
  - スマートフォン端末およびブラウザ（Safari / Chrome）の位置情報許可設定の手順を丁寧に案内。
- **サイト機能調整の必須チェック**:
  - お客様が特定のルート名・スポット名を挙げている場合、直ちに該当する `scripts/areas/<slug>.mjs` および `src/data/mock.ts` の座標（`lat`, `lng`）や住所を調査する。
  - 座標ズレやUIの不具合が確認できた場合は、**`AGENTS.md` の「AIリリース・品質保証規定（4ステップ）」** に従って修正・型チェック・サブエージェントレビュー・検証・`git push` まで自律実行し、お客様へ「ご報告いただいた箇所を修正いたしました」と回答する。

### ④ 退会（アカウント削除）のご依頼 (`withdraw`)
- **重要ルール**: `.agents/AGENTS.md` の「既存データの非破壊原則」により、AIエージェントが `users` や `stamps` テーブルを `DELETE` することは厳禁。
- **アクション**: 退会受付の丁寧な一次返信ドラフトを `draft` コマンドで作成し、ステータスを `NEEDS_REVIEW` にして運営者の承認・手動処理を仰ぐ。

### ⑤ 特定商取引法に基づく開示請求・その他 (`legal`)
- **アクション**: 必ず `draft` コマンドで下書きを作成し、`NEEDS_REVIEW` として運営者の確認待ちにする。
