# SHUIN デザイン＆UIコーディングガイドライン（Draft v0.1）

本ガイドラインは、AIが生成しがちな「汎用SaaS風・角丸カード乱立デザイン」から脱却し、SHUINの「和紙・墨・朱色・黄金」「散策的・風流・紙面（エディトリアル）のような手触り」を一貫して実装するための基準です。

---

## 1. 検証の前提
- **モバイル基準（375pxファースト）**: すべての画面設計・確認は、まず横幅 `375px`（片手持ちスマートフォン）で破綻なく、1〜3秒で意図が伝わることを最優先とする。

---

## 2. 造形・ビジュアルの基本ルール（アンチAI・デザイン原則）

### 2-1. 角丸（`border-radius`）の制限
- **原則**: 角丸は「紙面・印影・短冊」の端正さを保つため **最大 `2px〜4px`** に抑える。
- **禁止**:
  - `16px〜24px` 以上の大きな角丸カードで画面全体を囲むこと（和紙の背景の上に白い角丸の箱を重ねない）。
  - `30px` や `9999px` のカプセル型ボタンを標準にすること（バッジ等のごく一部の例外を除く）。

### 2-2. 情報の区切り方（カード・影・左ボーダーの禁止）
- **禁止**:
  - 情報を安易に白い角丸カード（`.glass-card` 等）やドロップシャドウ（`box-shadow`）で囲むこと。
  - 「角丸四角の左側に太い色線（`border-left`）を引いたコールアウト表現」を多用すること。
- **推奨**:
  - **極細の罫線（`1px solid rgba(17, 17, 17, 0.14)`）** と **余白** だけでセクションやスペックを区切る。
  - 背景色（和紙）の上に文字や写真を直接載せ、図録・書籍・観光パンフレットのような視線の流れを作る。

### 2-3. アイコンと装飾
- UIボタンや見出しに絵文字（🔍 🗺 🧭 🗾 など）を直接使わない。極細（`strokeWidth={1.8}` 前後）のモノクロ／朱色SVGアイコンか、端正なテキストのみで構成する。

### 2-4. 固定フッター（フローティングCTA）の原則禁止
- 画面最下部に常時追従するボタン帯は、上部アクションとの重複や375px画面の視界圧迫を招くため、原則配置しない。導線はページ上部と、コンテンツを読み終えた末尾に静的に置く。

### 2-5. リスト・工程（スポット一覧・ルート一覧等）の表現
- 要素ごとに白い角丸カードで囲わず、1pxの極細罫線と余白、丸囲みのない番号表記（`1.`, `2.` 等、地図ピンや他画面と統一した算用数字）で整理する。
- 工程間の移動目安は破線ピルを使わず、極細の縦線と文字のみで繋ぐ。
- 未ログインユーザーにとって不要な画面（押印専用ページなど）への導線は、「詳細を見る」等として出さず非表示にする。一方、ルート一覧のように遷移先に詳細情報がある場合は、遷移できることを明示する「詳細を確認」ボタンを各項に配置する。

### 2-6. アイキャッチ・スポット画像の和紙への馴染ませ方
- イラストや挿絵画像をパキッとした枠線で閉じ込めず、枠線（`border`）を排し、`mix-blend-mode: multiply` と四辺の柔らかいフェードマスク（`mask-image`）を用いて背景の和紙テクスチャに溶け込ませる。

### 2-7. データ0件（空状態）の非表示原則
- 「街角の余韻（旅人の足跡）」や参加者数などのコミュニティ情報・統計データは、0件のときに「まだ記録がありません」等の空状態を表示するとネガティブな印象になるため、データがない場合はセクション自体を非表示にする（`return null`）。

### 2-8. 本編と付録・回遊ゾーンの背景分離
- ルート本編（和紙背景）を抜けた後の「アンケート・他ルート検索・SEO案内」などの付録ゾーンや、探索帯のように背景色を変えて区切るブロックは、白い角丸カードで囲うのではなく、背景色の切り替えで役割の違いを表現する。**背景色が変わる境目には上下ともに不要な境界線（`border-top` / `border-bottom`）を引かない**（`1px` 罫線は同色背景同士を区切るときにのみ使う）。
- 無地背景（`#ECE7DC`）上のボタンやリンクは背景と同化しないよう、明るい面（`#FAF8F3`〜`#ffffff`）を敷いて押せる要素としての視認性を保つ。
- SNSシェアなどの横並び要素は長い日本語ラベルを並べず、コンパクトなアイコンボタン（`38px` 前後・`border-radius: 2px`）で視覚的に整理する。

### 2-9. 探索手段（探し方レイヤー）の統一と固定順序
- サイト全体のルート探索は以下の **3軸・固定順序（左からこの順）** に統一し、「一覧」という呼称・位置づけは使用しない。
  1. **検索して探す**（`/routes`）
  2. **地図から探す**（`/map`）
  3. **エリアから探す**（`/areas`）
- ヘッダー、トップページ、検索モーダル、ルート詳細下部の回遊導線、各探索ページ上部の3列切り替えバーすべてでこの名称と順序を厳守する。

### 2-10. 【重大NG】デザイン重視箇所での冗長ラベル・同語連呼の禁止
- トップページのアイコンナビなどデザイン性が求められる箇所で、すべてのアイコン下に「〇〇して探す」「〇〇から探す」「〇〇から探す」と**同じ動詞（「探す」など）を連呼して丁寧すぎる説明文を並べることは厳禁**。
- 共通の動詞・文脈は上部に1回だけ添える（例：`ルートを探す`）か省略し、各アイコン下は**最小限の1語（例：`検索` `地図` `エリア`）** に削ぎ落とす。

## 3. 情報階層・ファーストビューのルール

1. **タイトル優先（見出しが先、ビジュアルが後）**
   - 詳細ページを開いた瞬間（375pxのファーストビュー上部）に「どこの・何のページか」が即座に分かるよう、**地域・ジャンル（メタ情報）→ タイトル（H1）→ 画像 → 本文** の順で配置する。
2. **主役の本文は可読性を最優先（16px以上）**
   - ルートの説明など「最も読んでほしい本文」は、モバイルでも読みやすいよう **`1rem`（16px）以上** と十分な行間（`1.75〜1.8`）、高いコントラストを確保する。
3. **タグ・ラベルの機能的扱い**
   - 押せない・フィルタとして機能しない文字列（例：`愛知県・歴史・文化`）を角丸ピルで囲わない。単なる属性表示ならプレーンなテキストと区切り文字（`／` や `｜`）で表現する。
3. **視線を奪うスペック枠を作らない**
   - 所要時間・距離・予算などの数値データは、本文より目立って視線を奪わないよう、枠で囲わず「上下罫線のみのデータ行」として整理する。
4. **見出し・コピーの改行と文字数の原則（不用意な折り返し・孤立行の禁止）**
   - 375px幅（左右余白を除く有効幅約 `335px`）で見出しやキャッチコピーを置く際、文節の途中や助詞の直後で折り返して**短い孤立行（例：`〜、あなたの` / `しるしになる。`）を作らない**。
   - 1行あたり **全角16〜18文字前後** を目安にし、2文が続く場合や長くなる場合は意味の切れ目（句点・読点・文節）で明示的に行を分けるか、`text-wrap: balance` と文字サイズ調整で均整を取る。
5. **文字利用とアイコン置き換えの判断基準（ヘッダー等・狭小領域）**
   - **表示領域の確認**: 375px幅で他要素と並んだときに過密・圧迫・不自然な折り返しが起きないかを基準にする。
   - **アイコン・イラストへの置き換え可否**: アカウント（人型）やメニュー（☰）のように単一で直感的に伝わるものはアイコン化する一方、同じ空間に意味の似たアイコン（「地図」と「エリア」など）を文字なしで並べない。
   - **文字で表現せざるを得ない場合の文字数**: アイコン化できない場合のみ、表示幅に対して1行で無理なく収まる最小限の文字数に絞る。
   - **他部位との不整合チェック**: ヘッダーとファーストビュー・ページ本文で同じ機能の表記や密度が重複・矛盾していないかを確認する。
6. **モバイルのタップ領域と小アイコン並列アンチパターンの禁止**
   - 375pxモバイルでのタップ対象は最低 **`44px × 44px`** 以上を確保し、隣接ボタンと十分な間隔をとる（`36px` 以下の小アイコン密集は禁止）。
   - モバイルヘッダーは「アカウント／ログイン」と「メニュー（☰）」の最小構成（最大2点）に集約し、3つの探索軸（「検索して探す」「地図から探す」「エリアから探す」）はメニュー内に **アイコン＋文字** で大きく配置する。

## 4. アクション（ボタン）の3階層分離ルール

1つの画面に同格のボタンを縦一線に並べない。必ず以下の3階層に構造分離する。
また、**未ログインの初回訪問者は「登録しに来たのではなく、観光のやり方を見に来た」** ため、「ログインして〜」を第1階層（主アクション）に置かず、登録不要で今すぐ見られる「地図でルート・歩き方を見る」を主アクションにする。
ボタン内のラベルは **375px幅でも1行で収まる簡潔な文言**（例：`SHUIN帳を作る（無料）`）にし、不自然な折り返しを防ぐ。

| 階層 | 役割 | 表現ルール | 1画面あたりの数 |
| :--- | :--- | :--- | :--- |
| **第1階層（Primary）** | ユーザーに最も取ってほしい主行動（例：ルートに参加する） | 朱色背景・白文字の矩形（`border-radius: 2px`）。最も目立つ幅100%ボタン。 | **原則1つのみ** |
| **第2階層（Secondary）** | 参加前後の補助行動（例：地図で確認、保存する） | 透過背景＋1px細枠。原則 **2列横並び（`grid-template-columns: 1fr 1fr`）** 等でコンパクトにまとめる。 | 1〜2個 |
| **第3階層（Tertiary）** | 特定ユーザー向けの特殊行動（例：招待コードで合流） | ボタン化せず、下線付きテキストリンクや折りたたみとして控えめに配置する。 | 必要なだけ |

## 5. コーディング・CSS設計ルール

- ページ固有のレイアウト・ボタンスタイルは `page.module.css` に分離し、JSX内の長大な `style={{ ... }}`（インラインスタイル）を増やさない。
- 色は [globals.css](file:///Users/shintaro/stump-event/src/app/globals.css) のCSS変数（`--primary-color`, `--accent-color`, `--bg-color`, `--text-color`）を使う。
- 共通クラス（`.glass-card`, `.btn-primary` 等）は今後のデザイン統一時に段階的に本ガイドライン準拠へ刷新する。

## 6. UIレビュー・スクリーンショット目視チェック観点（人間目線での違和感排除）

「崩れていないか・横並びか」だけでなく、実装・修正後に **375px実画面のスクリーンショット** を見て以下を必ず点検する。

1. **近接の原則とラッパー寸法の一致**
   - アイコンサイズを変更した際、親ラッパー（`width` / `height`）の旧サイズが残って上下に透明なデッドスペースができていないか。
   - **アイコンとラベルの視覚的距離は `4px〜8px` 以内** に収め、タップ領域は外側ラッパーの `padding` や `min-width` で確保する。
2. **文字サイズと情報の優先度・サイズ感の一致**
   - 文字サイズが、その情報の重要度・優先度、および周辺のアイコンや余白のスケールと一致しているか。
   - 親見出し／グループ名（例：`ルートを探す`）が配下の子ラベルやアイコンに対して小さすぎないか、優先度とサイズ関係が逆転していないか。
3. **グルーピングとアフォーダンス**
   - 帯や余白の中にアイコンを裸で置いたとき、周囲の余白に負けて「ただの装飾」に見えていないか（押せそうなまとまり・視覚的アンカーがあるか）。
4. **同一ファーストビュー内の重複チェック**
   - 375pxのファーストビュー（スクロール前）で、ヘッダーとメイン領域に同じ導線や文言が不自然に二重表示されていないか。
5. **見出し・コピーの不自然な改行チェック**
   - 見出し・キャッチコピー・ボタンラベルが、375px幅で文節の途中に不用意な改行（孤立行）を生んでいないか。
