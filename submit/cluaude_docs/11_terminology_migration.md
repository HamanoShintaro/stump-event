## 概要

現行 Vercel版（<https://stump-event.vercel.app/>）には旧称・混在用語が残存している。Phase 1 MVP着手前または初期スプリント内に **全文一括置換** を行うこと。

本表は置換作業の差分管理用。

---

## A. ページ・コンポーネント

| 旧 | 新 | 影響範囲 |
|---|---|---|
| `みんなのスタンプラリー` | `SHUIN まちのしるし` | 全ページのフッター・OGP・metaタイトル |
| `スタンプラリー一覧` | `ルート一覧` | トップページ「注目の◯◯」セクション |
| `スタンプスポット` | `スポット` | /map ページ説明文 |
| `rallies/{id}` (URL) | `routes/{id}` | URLマイグレーション。旧URLは301リダイレクト必須 |

**URLマイグレーション注意:** `rallies/{id}` から `routes/{id}` への切替は、SNSシェア済みURL・QR印刷物への影響があるため **301リダイレクト** を半年以上維持。Phase 1 MVPでは両方アクセス可能。

## F. 置換作業の進め方

### Step 1: grep監査

```bash
# 現コードベースで旧用語を全件洗い出し
grep -rin "スタンプラリー\|スタンプを\|チェックイン\|スキャン\|ラリー\|クエスト\|ポータルクエスト" \
  --include="*.tsx" --include="*.ts" --include="*.jsx" --include="*.js" \
  --include="*.md" --include="*.json" .
```

### Step 2: 置換PR

- **用語置換PR** は機能PRと混ぜない。レビュー負荷を下げる。
- 置換PRのチェックリスト:
  - [ ] grep結果ゼロ件
  - [ ] OGP・metaタグ更新済
  - [ ] URLマイグレーション（301リダイレクト）設置済
  - [ ] DBマイグレーション（`rallies` → `routes`）スクリプトレビュー済

### Step 3: CI機械チェック追加

```bash
# CIで廃止語の混入を機械検出する lint rule
- name: Terminology check
  run: |
    if grep -rin "スタンプラリー\|チェックイン\|ラリー\|クエスト" \
       --include="*.tsx" --include="*.ts" src/; then
      echo "❌ 廃止語が混入しています。docs/10_glossary.md §0-6 を参照"
      exit 1
    fi
```

これにより以降のPRで廃止語が再混入することを防止。
