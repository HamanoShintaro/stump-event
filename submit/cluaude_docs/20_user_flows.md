## 1. 全体フロー図

```
[B② 入口] 隠れミッション型
協力店・街中のQR/NFCを偶然発見
       │
       ▼
アプリ起動（QRトークン送信）
       │
       ▼
Act 0 テキスト表示（80字・問いを渡す）
       │
       ▼
ルート選択画面（このQRに紐づく1〜複数ルート）
       │
       ▼
[A① コアループ] 常設ルート案内型
スポット1へ歩き出す
       │
       ▼ GPS 300m 検知
Act 1a バナー通知（60字・時代・人物・文脈の断片）
       │
       ▼ GPS 100m 検知
Act 1b バナー通知（50字・未解決の問い＋現地手がかり）
       │
       ▼ GPS 50m 検知
Act 2 バナー通知（30字・行動誘発で終わる）
       │
       ▼ ユーザーがスポット到達
押印（GPS半径50m以内 自動 or QR押下）
       │
       ▼
押印セレモニー F4〜F9（自動・約7秒）
       │
       ▼
ポストスキャンカード（F7全文・称号・次CTA）
       │
       ├─ [次のスポットへ] → マップ（次スポットハイライト）→ スポット2へ
       └─ [後で読む]      → マップ（通常表示）
       │
       ▼ 全スポット完走
完走セレモニー C1〜C4（自動・約5秒）
       │
       ▼
ポストルートカード（完走称号・全F7・SNSシェア）
       │
       ├─ [シェアする]       → ネイティブシェアシート
       ├─ [保存する]         → マップへ戻る
       └─ [次のルートを探す] → マップ（未完走ルートハイライト）
       │
       ▼
SHUIN帳に履歴追加 → 称号・累計来訪数加算
```

## 2. 入口パターン別フロー

### 2-1. B② 隠れミッション型（QR/NFC偶然発見）

```
1. 飲食店等に貼られたQRをスマホで読む
2. 未ログインの場合 → 簡易サインアップ（Google OAuth）
3. ログイン済の場合 → Act 0 直接表示
4. Act 0 完了後、このトリガーQRに紐づくルート一覧表示
5. ルート選択 → スポット1の方向案内開始
```

**重要:** QR読込後に「アプリストアに飛ばす」のは避ける。MVPはPWA前提で**インストール不要**で動くこと。ネイティブアプリ化はPhase 2以降。

### 2-2. A① 常設ルート案内型（マップから探す）

```
1. /map ページにアクセス
2. 現在地周辺のルートピンを表示
3. ピンをタップ → ルート詳細（/routes/{id}）
4. [ルートを始める] → スポット1の方向案内開始
5. 以降はB②と同じフロー
```

### 2-3. 既存ユーザーのリピート（SHUIN帳から再アクセス）

```
1. SHUIN帳（/lifelog）から未完走ルートを選択
2. 「次のスポット」を再度ナビゲート
3. 以降同じフロー
```

## 3. 押印（来訪証明）の判定フロー

```
ユーザーがスポット圏内（半径50m）に到達
       │
       ▼
クライアント: 位置情報を5秒おきに取得
       │
       ▼
半径50m以内検知
       │
       ▼
[押印ボタン表示] ← UX上の重要点: 自動押印しない。「押す」行為が儀式
       │
       ▼ ユーザーが押印ボタンタップ
POST /api/v1/checkin
  - body: { spot_id, lat, lng, qr_token? }
       │
       ▼
サーバー: Haversine距離計算
  - 50m以内 → OK
  - QRトークン一致 → OK（GPS不要のフォールバック）
       │
       ▼
重複チェック（同一user × spot × 当日）
レートリミット（10件/分/ユーザー）
       │
       ▼
stamp_event INSERT → stamp INSERT → 称号付与判定
       │
       ▼
レスポンス返却（来訪者番号・F7断片・F7全文・次スポット情報）
       │
       ▼
クライアント: 押印セレモニー F4〜F9 起動
```

詳細は [60_stamp_logic.md](./60_stamp_logic.md) 参照。

## 4. ナラティブ表示タイミング

ナラティブ（物語）は **5段階+1** で表示される。各幕の出現条件と表示位置:

| 幕 | トリガー | 表示位置 | 文字上限 |
|---|---|---|---|
| **Act 0** | QRスキャン（B②入口） | 全画面モーダル | 80字 |
| **Act 1a** | GPS 300m圏内検知 | バナー通知（プッシュ + アプリ内） | 60字 |
| **Act 1b** | GPS 100m圏内検知 | バナー通知 | 50字 |
| **Act 2** | GPS 50m圏内検知 | バナー通知 | 30字 |
| **F7断片** | 押印セレモニー F7（0.6〜1.2秒） | セレモニー画面 | 30〜40字 |
| **F7全文** | ポストスキャンカード | カード本文 | 120字 |

詳細は [61_narrative_logic.md](./61_narrative_logic.md) 参照。

## 5. ルート完走判定フロー

```
押印APIレスポンスの next_spot.is_final = true
       │
       ▼
ポストスキャンカードのCTAが「ルート完走 — 称号を受け取る」に変わる
       │
       ▼ ユーザーがCTAタップ
GET /api/v1/routes/{route_id}/completion-status
       │
       ▼
完走セレモニー C1〜C4（約5秒）
       │
       ▼
ポストルートカード表示
       │
       ▼
完走称号付与（badge_assignments INSERT）
ルート進行状態 → completed
```

## 6. エラー・例外フロー

| ケース | 挙動 |
|---|---|
| GPS取得失敗 | 「位置情報の権限を許可してください」モーダル → QRフォールバック誘導 |
| 圏外（50m超） | 「もう少し近づいてください（あと約◯m）」 |
| 重複押印（同日2回目） | 「既に今日このスポットを訪れています」（再訪はライフログには記録するが、SHUIN個数は加算しない） |
| QRトークン不一致 | 「このQRはSHUINに対応していません」 |
| サーバーエラー（5xx） | リトライ3回 → 「通信エラー。後で再試行してください」 |
| オフライン | 押印リクエストをキューに保存 → オンライン復帰時に自動送信（Phase 2機能） |

## 7. プッシュ通知トリガー一覧

| トリガー | 文言（例） | 配信タイミング |
|---|---|---|
| 近くに新ルート | 「新しいルートが始まっています」 | 半径1km以内の新規ルート公開時 |
| Act 1a検知 | 「呼ばれている — ◯◯まであと300m」 | バックグラウンド時のみ |
| 期限切れ間近イベント | 「◯◯ルート残り◯日」 | ③イベントルート締切3日前 |
| 称号獲得（バックグラウンド） | 「称号を授かった: ◯◯」 | アプリを閉じていた場合 |

通知のopt-in/opt-out管理は [40_api_spec.md](./40_api_spec.md) の `/api/v1/user/notification-settings` 参照。

## 8. オンボーディング（初回起動）

Phase 1 MVPでは **最小限のオンボーディング** とする。

```
1. SHUINロゴ・キャッチコピー（3秒・自動進行）
2. Google OAuth サインアップ
3. 位置情報の権限リクエスト
4. プッシュ通知の権限リクエスト
5. ホーム画面（マップ or おすすめルート）
```

チュートリアル動画やステップガイドは入れない。**「最初のスポットで押印するまでに3タップ以内」** を死守。
