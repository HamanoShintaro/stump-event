## 1. 役割

物理スタンプの多感覚体験（視覚・聴覚・触覚）をデジタルで再現する演出。SHUINの **「面白さの最低ライン」の一つ**。これが軽いと体験全体が成立しない。

---

## 2. 9フレーム構成（F1〜F9）— スポット押印

| F# | フェーズ | 所要時間 | 内容 | ハプティクス |
|---|---|---|---|---|
| F1〜F2 | 接近 | 数分〜 | GPS検知・バナー通知。「呼ばれた感」 | なし（バナーOSデフォルト） |
| F3 | スキャン | 3〜5秒 | カメラUI（QR時）・QR認識待ち / 押印ボタン表示（GPS時） | なし |
| F4 | 押下 | 0〜0.3秒 | 画面暗転・漸増ハプティクス | 漸増（弱→中） |
| F5 | 押下 | 0.3〜0.5秒 | スタンプ降下（ease-in重力アニメ） | 急増（中→強） |
| F6 | 押下 | 0.5〜0.6秒 | インパクト・インク広がり開始 | **最大ハプティクス（単発）** |
| **F7** | 押下 | **0.6〜1.2秒** | **物語片（F7断片・30〜40字）＋スポット名・来訪日時の刻印** | 余韻×2（弱） |
| F8 | アフターグロー | 1.2〜3.5秒 | 来訪者番号「#47番目」＋次称号までの残スポット数 | なし |
| F9 | アフターグロー | 3.5〜7秒 | SHUIN帳ビュー。新スタンプ追加アニメ後 → ポストスキャンカードへ | なし |

**初回来訪のみフルセレモニー**。再訪時は省略（場所の希少性担保）。

---

## 3. F7 の重要分離（断片 vs 全文）

**2つのF7が存在する。これを意図的に分離する。**

| 種別 | 表示タイミング | 文字数 | 内容 | 設計意図 |
|---|---|---|---|---|
| **F7断片** | セレモニー中（0.6〜1.2秒、自動） | 30〜40字 | F7全文の冒頭1文 | 好奇心維持。全文表示は次行動の動機を消す |
| **F7全文** | ポストスキャンカード（ユーザーペース） | 120字以内 | Act 1bの答え＋次スポット引力 | 物語の完結感 |

**理由**: セレモニー中に120字読ませると演出の「重み」が散漫になる。断片で余韻を作り、全文はユーザーが自分のペースで受け取る。

実装上の責務分離:
- F7（セレモニー） → `narrative.f7_fragment` のみ表示
- F7（ポストスキャンカード） → `narrative.f7_full` を表示

## 4. ルート完走セレモニー（C1〜C4）

スポット押印セレモニーとは **設計意図が異なる**。スポットは「到着の瞬間」、完走は「旅の収束」。

| ステップ | 時間 | 内容 | ハプティクス |
|---|---|---|---|
| C1 | 0〜0.5秒 | 画面フェードアウト（黒）。静寂 | なし |
| C2 | 0.5〜2.0秒 | ルート内の全スポットSHUINが左上から順に1個ずつ出現（0.2秒/個）。最後だけ0.5秒遅れて大きく出現 | スタンプ1個ごとに軽いノック×n。最後に中強度インパクト |
| C3 | 2.0〜2.5秒 | スタンプ群が小さく収縮し、画面中央へ集まる | 収縮完了時に弱い振動×1 |
| C4 | 2.5〜5.0秒 | **ルート完走称号カードがスライドイン（下から）**。称号名・英字サブタイトル・ルート名・★表示が順番に現れる | カードフル表示時に最大強度インパクト×1（F6相当） |

**設計意図**: C2でこれまでの全スポットを走馬灯のように見せることで「旅の収束感」を作る。スポットが3個でも5個でも同じ演出が使える。

C4 終了後 → ポストルートカード（[52参照](./52_post_route_card.md)）。

## 5. 技術スタック

| 要素 | 推奨 |
|---|---|
| アニメーション | React Native Reanimated v3 / Framer Motion（Web） |
| ハプティクス（iOS） | expo-haptics |
| ハプティクス（Android） | react-native-haptic-feedback |
| 画面遷移 | React Navigation / Next.js layout（Web） |
| 音声（オプション） | expo-av |

**MVPは音声なし**（環境音への配慮・実装簡略化）。Phase 2で検討。

---

## 6. アクセシビリティ

- **ハプティクス無効化オプション**: 設定画面から ON/OFF
- **モーション削減オプション**: OSの「視差効果を減らす」設定を尊重。減らす設定時は F5（スタンプ降下アニメ）を簡略化
- **スクリーンリーダー対応**: 各フレーム遷移時に `aria-live` で内容を読み上げ

---

## 7. パフォーマンス要件

| 項目 | 基準 |
|---|---|
| F4 開始までの遅延 | API応答後 100ms以内 |
| F4〜F9 通算 | 7±0.2秒（±200ms許容） |
| アニメーションFPS | 60fps 維持 |
| ハプティクス遅延 | アニメーションと±50ms以内 |

低スペック端末でフレーム落ちする場合は、F5のease-inを線形に簡略化（重みは維持）。

---

## 8. エラーハンドリング

| ケース | 挙動 |
|---|---|
| API応答中（>3秒） | F3 にローディング表示。タイムアウト10秒で「通信エラー」表示 → リトライ |
| ハプティクス権限なし（Web） | サイレントに無効化、視覚演出のみ |
| 画面ロック・バックグラウンド遷移 | セレモニー中断 → 復帰時にF8から再開 or 直接ポストスキャンカード |

---

## 9. 状態遷移図（押印フル）

```
IDLE
  → [QR認識 or GPS圏内+ボタン押下] → API POST /checkin
  → CEREMONY_F4 → F5 → F6 → F7（断片表示）
  → F8（来訪者番号）→ F9（SHUIN帳）
  → POST_SCAN_CARD（F7全文＋称号＋CTA）
  → [次のスポットへ]   → MAP（next_spot_highlighted）
  → [後で読む]         → MAP（通常表示）
```

---

## 10. 状態遷移図（ルート完走フル）

```
POST_SCAN_CARD（最終スポット）
  → [ルート完走称号を受け取る] タップ
  → API GET /routes/{id}/completion-status
  → COMPLETION_CEREMONY_C1 → C2 → C3 → C4
  → POST_ROUTE_CARD（ユーザーペース）
  → [シェアする]       → ネイティブシェアシート → 戻る
  → [保存する]         → MAP（通常表示）
  → [次のルートを探す] → MAP（未完走ハイライト）
```
