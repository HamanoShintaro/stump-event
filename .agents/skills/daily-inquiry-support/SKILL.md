# SHUIN 日次お問い合わせ対応＆自律イテレーションスキル (`daily-inquiry-support`)

このスキルは、毎日12:00（JST）の定期実行、またはユーザーからの「今日のお問い合わせをチェックして」「サポート対応を進めて」という依頼時に、以下の4ステップを順番に実行するための標準ランブックです。

---

## Step 1: 前日対応の振り返り（Retrospective）＆ プレイブック更新

対応を始める前に、まず過去の対応品質を振り返り、1日ごとに精度を向上させるイテレーションを行います。

1. `docs/support/playbook.md` と、`docs/support/daily_logs/` 内の直近のログファイルを `read_file` で読み込みます。
2. `node /Users/shintaro/stump-event/scripts/manage-inquiries.mjs list --days 7` を実行し、直近のお問い合わせ状況を確認します。
3. 前回対応したお客様から再度の質問（解決不足による再問い合わせ）が来ていないか、また `NEEDS_REVIEW`（確認待ちドラフト）の案件やサイト改善後の状況を確認します。
4. 振り返りから得られた学び（より分かりやすい案内表現、新たに判明したよくある質問、事前にチェックすべきコード箇所など）があれば、`docs/support/playbook.md` の「3. カテゴリ別・標準回答ガイドライン」および「4. 日次イテレーション・フィードバック履歴」を `edit_file` で更新します。

---

## Step 2: 未対応お問い合わせ（`OPEN`）の分析・回答送信・ドラフト作成

1. Step 1 で取得した `open_inquiries`（`status = "OPEN"`）を1件ずつ精査します。
2. `docs/support/playbook.md` の振り分け基準に従い、各お問い合わせに対して以下のいずれかを実行します：
   - **A. よくある質問・一般的なご案内・仕様説明・修正完了報告（自動返信対象）**:
     - 禁止用語（「スタンプラリー」「ラリー」「ナラティブ」「スタンプ」「挑戦する」「クリアする」）が一切含まれていないことを確認したうえで、丁寧な返信文を作成し、以下のコマンドで送信＆ステータス更新（`REPLIED`）を行います：
       ```bash
       node /Users/shintaro/stump-event/scripts/manage-inquiries.mjs reply --id "<id>" --subject "【SHUIN まちのしるし】お問い合わせありがとうございます" --body "<本文>"
       ```
   - **B. 個別判断が必要なもの（返金・決済トラブル・退会削除実行・法務関連・重大障害）**:
     - 一次返信の下書き（ドラフト）と判断理由を作成し、以下のコマンドで `NEEDS_REVIEW` として記録＆通知します（AIが独断でDBのユーザーデータをDELETEしたり返金確定を行ったりすることは厳禁）：
       ```bash
       node /Users/shintaro/stump-event/scripts/manage-inquiries.mjs draft --id "<id>" --subject "【SHUIN まちのしるし】お問い合わせの件について" --body "<下書き本文>" --reason "<確認が必要な理由>"
       ```

---

## Step 3: お問い合わせを起点としたサイト機能の調整・自律リリース

お問い合わせ内容から「サイトの案内文（`/guide` 等）を改善すれば今後同じ疑問を防げる」「特定のスポットの座標や説明文に誤りがある」「UIの不具合がある」と判断した場合は、根本解決のためサイト調整を行います。

1. 該当するコードやデータ（`src/app/guide/page.tsx`, `src/app/contact/page.tsx`, `scripts/areas/<slug>.mjs`, `src/data/mock.ts` 等）を調査・修正します。
2. **必ず `AGENTS.md` の「AIリリース・品質保証規定（4ステップ）」を順番に実行します**：
   - **Step 3-1 (分離ステージング・型チェック・ローカルコミット)**:
     - 関係するファイルのみを `git add <file>` し、`npx tsc --noEmit` で型エラー0件を確認してローカルコミットします。
   - **Step 3-2 (レビュー専任サブエージェントによる独立チェック)**:
     - `invoke_subagent`（`research` または `self`）を起動し、`git show HEAD` の差分にロジック不具合・禁止用語・`window.alert` 使用・DB破壊操作がないか第三者レビューを行います。
   - **Step 3-3 (サンドボックスでの画面・ロジック検証)**:
     - ビルドまたは開発サーバー等でエラーなく動作することを確認します。
   - **Step 3-4 (`git push`)**:
     - すべてのチェックを通過した後に `git push origin main` を実行します。

---

## Step 4: 日次サポート＆イテレーションレポートの記録

最後に、本日の対応内容と振り返りを `docs/support/daily_logs/YYYY-MM-DD.md` に保存します。

- **記載項目**:
  1. **🔄 前日振り返り（Retrospective）と本日プレイブックへ反映した改善点**
  2. **📊 本日の受信・対応サマリー**（新規件数、自動返信件数、要確認ドラフト件数、直近7日間の傾向）
  3. **✉️ 個別お問い合わせ対応詳細**（ID、種別、要約、送信した回答または確認待ちドラフト全文）
  4. **🛠️ 実施したサイト機能・文言の調整**（コミットID、サブエージェントレビュー結果、検証結果）
  5. **🎯 明日以降のイテレーション課題**
- ログファイルおよび `playbook.md` の更新分も `git add docs/support/` → `git commit` → `git push` でリポジトリへ永続化します。
