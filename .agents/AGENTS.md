# データベース操作・更新ルール (Database Safety Rules)

AIエージェントが本プロジェクト（SHUIN）で SQL の実行やシードスクリプトの作成・実行を行う際、以下のルールを必ず厳守してください。

1. **既存データの非破壊原則 (No Destructive SQL/Seed)**
   - テストや本番を問わず、データベース内の既存のユーザー履歴データ（特に `stamp_events`, `stamps`, `users`, `group_members` など）を **削除（DELETE）、クリア、または改変する操作は原則禁止** とします。
   - ルートやスポット、バッジなどのマスターデータを新規追加・更新する際は、既存データを一括削除して再インサートする方式（破壊的シード）ではなく、`INSERT ON CONFLICT DO UPDATE` (UPSERT) を使用して、差分のみを安全にマージする方式を徹底してください。

2. **カスケード削除の防止 (Prevent Cascade Deletes)**
   - `routes` や `spots` などのマスタレコードを削除すると、外部キー制約の `ON DELETE CASCADE`（連鎖削除）により、ユーザーがこれまで獲得してきたしるし（スタンプ）データが道連れで消去されてしまいます。
   - マスターデータのクリーンアップが必要な場合は、事前にユーザーデータを別テーブルへ退避するか、ユーザーの明示的な承諾・指示を得てから安全な計画のもとで実行してください。
